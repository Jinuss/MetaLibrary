# 移动端排版规范

民生文章的读者多在通勤、排队、睡前用手机读。排版的目标是让他「扫一眼就抓住重点」，而不是「读完一遍」。

## 一、阅读前提

- 95% 以上读者在手机端阅读，屏宽约 375px，一屏约 12-14 行
- 读者平均停留时间短，第一屏决定是否继续
- 所以：结论前置、重点加粗、段落短小

## 二、基础参数

| 项目 | 推荐值 | 说明 |
| --- | --- | --- |
| 正文字号 | 15-16px | 14px 偏小，17px 偏大 |
| 正文颜色 | `#3F3F3F` 或 `#333333` | 纯黑 `#000` 在手机上对比过强，读久刺眼 |
| 行间距 | 1.75 或 2.0 | 低于 1.5 会显得挤 |
| 字间距 | 0.5-1px | 中文略微拉开更好读 |
| 段间距 | 与行间距相当，靠空行实现 | |
| 对齐方式 | 左对齐 | 两端对齐会把中文词距拉得忽大忽小 |
| 页边距 | 左右 0-8px | 微信默认已留边距，不要再加缩进 |

## 三、段落规则

- 每段 1-4 行，超过 4 行必须拆
- 段与段之间空一行
- **不用首行缩进** —— 微信里缩进会破坏整体留白，看起来反而乱
- 一句一段可以，用于强调关键结论
- 篇幅建议：
  - 政策解读类 1200-2000 字
  - 办事指南类 800-1500 字
  - 超过 2500 字考虑拆成系列或上 / 下篇

## 四、加粗与强调

- 每屏（约 12 行）加粗不超过 2-3 处；加粗太多等于没加粗
- **优先加粗**：具体数字、金额、时间节点、办理条件、关键结论
- **不要加粗**：整句话、大段文字
- 全文强调色只用一到两种。民生类建议低饱和的深红 `#A62B2B` 或深蓝 `#1F4E79`，避免荧光色和渐变

## 五、小标题

- 用加粗短句，**句尾不加冒号**
- 长度 8-15 字
- 不用「一、二、三」加对仗排比的八股写法
- 小标题上方留 1.5 倍行距，与上文拉开层次
- 可选：小标题前加统一小符号（`▪` 或 `｜`），全文保持一致，不要每节换花样

## 六、配图

- 封面：900×383px（2.35:1）
- 正文图：宽度 1080px，PNG-24
- 每 400-600 字配一张图，起分隔与呼吸作用
- 图注用小号灰字居中
- **避免**：花哨边框、水印压正文、来源不明图片（民生类尤其注意版权与人物肖像授权）

## 七、引用与数据

- 引用政策原文：用引用样式（左侧竖线 + 灰底）或斜体灰字，与正文区分
- 关键数据做成小卡片：浅底 + 加粗数字，比埋在段落里好读
- 表格在手机上最多 3 列，超过就改成分条列表

## 八、开头与结尾

- **开头**：不放「关注我们」「点击上方蓝字」这类引导，第一屏就上内容
- **结尾**：固定区域放「往期推荐 / 相关阅读 / 留言互动」，用分割线与正文隔开
- 全文不堆砌 emoji；小标题如需使用，每节最多 1 个且风格统一
- 结尾互动引导要具体：「你所在的城市办这项业务需要几天？留言说说」，比「欢迎留言」有效

## 九、HTML 输出要求

- 使用 `assets/wechat-article-template.html` 作为骨架
- **所有样式必须内联** —— 微信编辑器会剥离 `<style>` 标签和 `class` 依赖的外部 CSS
- 不使用 `<script>`
- 外层用 `<section>` 包裹，减少粘贴时丢样式
- 段落用 `<p style="...">`，靠 `margin` 控制间距，不靠空 `<p>` 撑高度
- 粘贴进公众号编辑器后，再按账号自身模板微调字号与行距
- 图片位置用占位注释标注（`<!-- 图 1：xxx -->`），由运营在编辑器内插入

### 表格范式（内联样式，可直接套用）

手机上最多 3 列；超过 3 列就改成分条列表。整表用 `table-layout:fixed` + 百分比列宽，保证粘贴后不跑版。

```html
<table style="width:100%;border-collapse:collapse;font-size:14px;color:#3F3F3F;line-height:1.6;margin:0 0 14px 0;table-layout:fixed;">
  <tr>
    <td style="width:22%;padding:9px 6px;border:1px solid #E5E5E5;background:#F7F7F7;font-weight:bold;color:#222222;vertical-align:top;">列一</td>
    <td style="width:55%;padding:9px 6px;border:1px solid #E5E5E5;background:#F7F7F7;font-weight:bold;color:#222222;vertical-align:top;">列二</td>
    <td style="width:23%;padding:9px 6px;border:1px solid #E5E5E5;background:#F7F7F7;font-weight:bold;color:#222222;vertical-align:top;">列三</td>
  </tr>
  <tr>
    <td style="padding:9px 6px;border:1px solid #E5E5E5;vertical-align:top;">…</td>
    <td style="padding:9px 6px;border:1px solid #E5E5E5;vertical-align:top;">…</td>
    <td style="padding:9px 6px;border:1px solid #E5E5E5;vertical-align:top;color:#888888;">…</td>
  </tr>
</table>
```

- **不用** `<thead>` / `<tbody>` / `<th>`，只用 `<tr>` / `<td>` —— 兼容性最好，粘进公众号编辑器不掉样式
- 表头行靠 `background:#F7F7F7` + `font-weight:bold` 实现，不用 `<th>`
- 字号降到 13-14px（正文是 16px），否则三列在手机上会挤
- 表格下方补一行 14px 灰字，写清口径与免责说明（如「以当地公告为准」）
- 表格行在 `selfcheck.py` 中不参与段落与句长统计，不会被误判为超长段落

## 十、排版自检

1. 在手机上预览一遍，第一屏能不能看到核心结论？
2. 有没有连续 5 行以上没有换段的「文字墙」？
3. 加粗的位置，是不是读者最需要记住的信息？
4. 小标题单独看，能不能串起全文的骨架？
5. 全文符号、颜色、字号是否统一？
