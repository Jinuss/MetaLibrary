# 项目长期约定（article）

## 账号定位

- **全国号**，不是地方号。全国性题材（天气、政策、消费）保持全国视角，**正文与表格不下钻到单一城市**，除非该城市本身是全国性焦点（如北京、上海、广州）。
- 地方内容按**省级**或"省级 + 多城并列"表述；不因前一篇稿子涉及某地就在后续文章里惯性突出该地。

## 产出位置与命名

- 文章产出在 `article/` 根目录：`YYYY-MM-DD-主题.html`（一键复制页）+ 同名 `.md`（源稿）。
- 根目录除文章文件外只应有 `.workbuddy/`。出现 8 位随机名、4 字节、内容为 `blat` 的文件 = 沙箱临时垃圾，直接删。判据用「根目录 + 4 字节」即可，无需逐个校验内容。每跑一次沙箱内自检约产生 20 个；删除须跳出沙箱执行，沙箱内 `-delete` 会报 Permission denied。

## 语体与格式（用户明确要求）

- 正文用**官方通稿语体**：陈述事实与后果，不替读者下结论、不催动作、不抖机灵。
- 禁止 AI 腔：口语化短句收尾（"比什么都准""别拖到最后几天"）、加粗短句打头、祈使式叮嘱（记得/千万别/一定要）。
- 中文标点一律全角，引号用 `“ ”`；标题不超过 64 字且不含冒号。
- 成稿必须跑 `scripts/selfcheck.py` 兜底，零 ERROR 零 WARN 才算完成。

## 交付与编码

- HTML 存 UTF-8 无 BOM（头字节应为 `3c2144`），样式全内联，可一键复制到公众号后台。
- 表格最多 3 列，`table-layout:fixed` + 百分比列宽，不用 `<th>/<thead>`。

## 结构与编排（用户 2026-09-30 确认）

- **快查信息前置**：城市/景区等速查表放在「全国概况」之后、「分区域」之前，让读者第 2 屏拿到答案。
- **小标题用读者自己的词**：一律用省份名、城市名，不用气象区名（江淮/黄淮/江汉）和行业术语——读者无法判断自己属哪个区，且这类词在搜一搜里是零命中。唯一例外是专业统计口径（如气温距平按江南、华南发布），改动会失真，保留。
- **同一信息不重复**：与表格重复的城市单列条目一律删除；正文只留表格覆盖不到的增量。
- **必须有民生落点**（用户 2026-09-30 明确）：本号是民生号，不是资讯号。任何题材都要回答"所以呢"——删掉这篇文章，读者损失的是「知道了」还是「用得上」。天气稿必须落到出行（高峰时段、免费政策）、安全、体感；政策稿落到谁能办、怎么办、何时截止。落点用**事实与后果**陈述，不用叮嘱口吻（写"临近 24 时截止时点部分路段可能集中驶出"，不写"建议提前下高速"）。
- **天气稿优先补交通**：交通部门（交通运输部、公安部交管局、各省交通运输厅）的出行提示里有现成的官方预测——高速免费时段、流量峰值日、出程/返程高峰时段，比气象数据更贴近读者的动作，值得单独成节。
- **标题也要有落点**（用户 2026-09-30）：题材词（"天气""政策"）只说明写的是什么，落点词（"高速免费 7 天""最高 1 万元"）才说明读者能得到什么。标题须含至少一个落点词，并压在列表页展示的前 20 字内；核心检索词完整前置（如"国庆假期天气预报"是一个真实高频搜索词）。

## 数据口径

- **景区/景点天气分两级取数**：有景区专项预报就用专项（中国气象局名山稿件、市气象台景区专报），没有才用所在城市预报并在表注写明。
- 气温必须标明取值位置（山顶/山上/高山/市区），景区名后标所在地，如「泰山（山东泰安）」。
- 商业聚合源（天气 App、trip.com、天气网子站）不作依据；只用气象局系统与官方媒体转载。

## 自检脚本

- `selfcheck.py` 中表格字数单列，`body_text_len`（不含表格）才用于体量判定；判定标准是非表格正文 600～3000 字。
- 表格相关正则一律用 `[ \t]` 而非 `\s`，避免吃掉换行导致表格行被拼成一句。
