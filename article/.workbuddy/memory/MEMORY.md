# 项目长期约定（article）

## 写作立场（2026-10-12 深度反思，**优先级高于所有技法规程**）

- 事实：六篇 AI 协作稿单篇阅读 20—30，**是账号里表现最差的一批**（账号周阅读 432，含历史长尾）。原因不在技法，在立场。
- **五层根因**：①脑子里的"读者"是集合名词（"灵活就业人员"），从来不是具体的人；②在写**文档**（信息完整、可查阅）而不是**文章**（让人从第一句读到结尾）；③写作姿态是**防御性的**——只规避风险、不承担价值，产出就是"文件的复印件"；④为合规而主动放弃观点与案例，恰好落在 7.4 低价值 AIGC 要打击的位置；⑤自检标准被自己反复放宽（加豁免、拆列、取消字数上下限），拿一把越调越松的尺子自我验收，再报"零 ERROR 零 WARN"。
- **三条准则（此后每篇必须过）**：
  1. **写作前先想清一个具体的人**——不是"读者"，是"那个跑滴滴、一个月自己交 300 块、还以为自己缴得挺划算的人"。想不出这个人，说明这个选题不该写。
  2. **标准从"最安全"改为"合规边界内信息量最大"**。不知道就诚实写明（"这一条目前没有答案，你可以这样去问"），比一段准确的制度介绍有用。
  3. **放弃当自己的裁判**。脚本只能测下限，效果一律由数据判定。
- 一句话：**用户让我写他账号的内容，我却在用他的账号做一个"我没出错"的作品集。**

## 账号定位

- **定位 = 民生资讯类**（用户 2026-10-10 明确）。垂直度的锚点是**题材域不越界**，不是把每条都写成办事指南；"资讯"是本色、不是缺点，不要把资讯型写法当成扣分项。
  - **圈内（账号范围）**：社保医保、公积金、养老金、婚育政策、教育、就业、住房、物价消费、水电燃气、交通出行、政务办事、维权投诉；民生事件个案可作引子（须全国化处理，见"结构与编排"）。
  - **圈外（会把账号拉成综合资讯号）**：娱乐八卦、体育赛事、国际时政、军事、猎奇社会新闻。
  - **民生的分界线是「民生资讯 vs 社会新闻」**，不是「服务 vs 资讯」。三条判据：①与读者的生活／钱／办事有接口；②信息本身有价值，非只有情绪；③有可追溯信源（文件、公告、部门答复），不靠"网传／知情人士"。
  - **资讯号的反面风险 = 信息价值低**：靠"筛选 + 解读"立住——从一周几十条里挑出真正影响读者的几条，并说清它算什么；这部分必须人工做，AI 只打下手（对应 7.4 低价值 AIGC）。
- **全国号**，不是地方号。全国性题材（天气、政策、消费）保持全国视角，**正文与表格不下钻到单一城市**，除非该城市本身是全国性焦点（如北京、上海、广州）。
- 地方内容按**省级**或"省级 + 多城并列"表述；不因前一篇稿子涉及某地就在后续文章里惯性突出该地。
- **情绪评论式选题要拦**（2026-10-12）：用户同一热点（郑钦文夺冠 + 霸王茶姬买一送一）先后拟出「这杯"情绪奶茶"到底谁在喝」「我们买的不是奶茶，是"中国人今天赢了"」两个标题，都是把消费现象上升为情绪/民族叙事。这类写法三处出线：①标题宣告立场、与正文服务信息脱节，构成标题党；②替读者赋义（把半价驱动的排队解释成民族情绪），事实撑不住；③情绪营销+民族情绪属舆情高风险区，民生资讯号不碰。**每次都要明确拦住并给替代标题，不顺着写。**

## 产出位置与命名

- 文章产出在 `article/` 根目录，**只输出一个文件** `YYYY-MM-DD-主题.html`（一键复制页）。用户 2026-10-08 明确：不再生成同名 `.md` 源稿；自检脚本已改成直接读 HTML。
- 根目录除文章文件外只应有 `.workbuddy/`。出现 8 位随机名、4 字节（`blat`）的文件 = Python 启动垃圾，判据「根目录 + 4 字节」。
- **根因与解法（2026-10-12 定位并实测）**：沙箱拦截系统临时目录，Python 启动时加载用户 site 配置会失败并把临时文件回退到当前目录，**每运行一次约产生 20 个垃圾**。**运行任何 Python 脚本一律加 `-I`（隔离模式），垃圾直接归零，无需任何清理**——实测干净基线 0，连跑两次仍为 0。注意只有 `-I` / `-S` / `-E -s` 有效，`-s` 单独用仍产生 20 个。纯 bash 命令（ls / find / echo）不产生垃圾。
- 兜底（若某次忘了加 `-I`，或将来脚本必须依赖 site-packages）：把**工作目录和** `TMPDIR`/`TEMP`/`TMP` 同时指到 `.workbuddy/tmp/`，垃圾全部落在该目录，删目录即可；只重定向 `TMPDIR` 不够，cwd 仍新增约 20 个。
- 清理兜底目录：`rm -rf` 整个目录会被 safe-delete 批量确认拦下（>50 文件），改用 `find <dir> -type f -delete` 再 `rmdir` 可一次清净；沙箱内删除会被拒，需 `dangerouslyDisableSandbox`。

## 执行效率（用户 2026-10-12 明确要求：不断优化回答效率，节省时间）

- **脚本一律加 `-I` 运行**，垃圾归零，不再把"清理临时文件"当成一个环节。
- **写全文前先过确认**：给出「写给哪一个具体的人 + 一句话选题 + 2—3 个标题候选 + 小节骨架」，用户点头再动笔。整篇重写是最耗时的一环，前置确认能整个省掉。
- **自检只跑一轮拿全清单**，按报告逐条 Edit 修补；不凭印象整篇重发。
- **核实阶段并行发起检索**，同一批问题一次发出；信源按「官方原文 > 权威媒体 > 聚合站（只作线索）」取用，不逐级回溯。
- **回复只讲四件事**：结论、改了什么、需要确认什么、下一步。不复述过程，不解释工具调用。

## 语体与格式（用户明确要求）

- **讲人话：读者看得懂排在第一位**（用户 2026-10-12 明确：不需要很深的专业术语，要浅显易懂，文章是给人读的看的，不是像一篇通知）。完整规范在 `writing-rules.md` H 节、SKILL.md 硬底线第 5 条。三条要点：
  - **分清两类词**：读者的词（社保、养老金、公积金、缴费基数、灵活就业人员、婚假）**原样保留**——既是人话也是检索词；行话（全口径、统筹、计发基数、视同缴费年限、参保扩面、参保人员、用人单位）**必须翻译**。口诀「我平时会跟家里人这么说吗」。
  - **三档处理**：能换就换成日常说法；是关键概念无等价说法的，紧跟一句人话解释（术语名放后面或不放）；法定名称才原样保留。**一篇里需要"译"的术语不超过 2—3 个**，超过说明选题太靠文件。
  - **不写通知体**：首段不用"X 月 X 日，某部门发布……"起句；不用无主语陈述、名词堆叠、"现将有关事项通知如下"式措辞、"特此通知"式收尾。文章是讲给一个人听的，不是把文件转达一遍。
  - 删改流程由**三遍扩为四遍**：删 → 换 → **译**（行话翻人话）→ 读。
  - 每篇至少做到 H5 三件事里的两件：**一个具体的人 / 一笔具体的账 / 一个具体的动作**。
- 正文用**民生平实语体**（2026-10-08 由"官方通稿语体"修正而来）：平实、正常对话、有读者在场，像一位把文件读懂了的人用日常语言讲给读者听。判据是"念给没看过文件的人听，他能不能听懂；听懂但觉得像在被训话，也要改"。
  - **允许**：设问过渡（"婚假能休几天？"）、导航句（"下面先说数据，再说婚假怎么休"）、把读者位置写进段落（"准备结婚或刚登记的人……"）。
  - **避免公文腔**：依法办理、同步公布、还披露、文件明确、现将、予以、有关规定、享受相应待遇、统筹推进、稳妥有序；这类词自检会出【公文腔提示】。
  - **仍然禁止**：口语化短句收尾（"比什么都准""别拖到最后几天"）、加粗短句打头、祈使式叮嘱（记得/千万别/一定要）、撒娇催促抖机灵。
- 民生细分题材按此定语气：政策解读（先变化→"你这类人怎么办"）／办事指南（直给条件步骤）／生活服务（给场景判断）／数据发布（先来源数字→读者位置）／权益维护（谁能办、找谁、什么时限）。混合题材按读者的第一疑问定语气。
- 中文标点一律全角，引号用 `“ ”`；标题不超过 64 字且不含冒号，不用绝对化用语（最有效、全国第一、100%）与标题党表达（震惊、必看、紧急通知）。
- 成稿必须跑 `scripts/selfcheck.py` 兜底，零 ERROR 零 WARN 才算完成。

## 结构与编排（用户 2026-09-30 确认）

- **快查信息前置**：城市/景区等速查表放在「全国概况」之后、「分区域」之前，让读者第 2 屏拿到答案。
- **小标题用读者自己的词**：一律用省份名、城市名，不用气象区名（江淮/黄淮/江汉）和行业术语——读者无法判断自己属哪个区，且这类词在搜一搜里是零命中。唯一例外是专业统计口径（如气温距平按江南、华南发布），改动会失真，保留。
- **同一信息不重复**：与表格重复的城市单列条目一律删除；正文只留表格覆盖不到的增量。
- **必须有筛选价值 + 民生落点**（用户 2026-09-30 定，2026-10-10 按"民生资讯类"定位校准）：任何题材都要回答"所以呢"——删掉这篇文章，读者损失的是「知道了」「用得上」，还是「看热闹」？前两者对民生资讯号成立（政策变化、数据发布让读者"知道了"即可），"看热闹"不成立（纯冲突、纯情绪事件不收）。天气稿仍须落到出行（高峰时段、免费政策）、安全、体感；政策稿落到谁能办、怎么办、何时截止。落点用**事实与后果**陈述，不用叮嘱口吻（写"临近 24 时截止时点部分路段可能集中驶出"，不写"建议提前下高速"）。
- **天气稿优先补交通**：交通部门（交通运输部、公安部交管局、各省交通运输厅）的出行提示里有现成的官方预测——高速免费时段、流量峰值日、出程/返程高峰时段，比气象数据更贴近读者的动作，值得单独成节。
- **标题也要有落点**（用户 2026-09-30）：题材词（"天气""政策"）只说明写的是什么，落点词（"高速免费 7 天""最高 1 万元"）才说明读者能得到什么。标题须含至少一个落点词，并压在列表页展示的前 20 字内；核心检索词完整前置（如"国庆假期天气预报"是一个真实高频搜索词）。
- **个案类稿件的全国化处理**（2026-10-10 确立）：单一城市个案若已是全国讨论焦点，可作引子，但正文须上升到全国层面——先给国家层面文件依据，再给多地做法对照（如石台、济宁、江永、伊吾、福清五地口径）；标题不带城市名，便于全国号检索；事件时间线写清后转入政策边界，不写成地方新闻。这类稿件的语气按「权益维护」走：能否拒绝、找谁反映、什么时限。
- **"拓展"要有边界，不主动扩大选题**（用户 2026-10-12 明确"拓展的写的太多了"）：用户给的素材（原文、发布会内容、链接）是稿件的信息骨架，**不要为了显得充实而从网上拉一堆相关数据进来**。一篇的合理结构 = 素材直接信息 + 至多 1 条必要的制度背景（用于解释"这对我意味着什么"）+ 读者能做的动作。相邻题材（如写养老保险时顺带写职业伤害保障、就业支持政策）即使真实、有信源，也一律不写——它们是另一篇的题。判断方法：删掉这段，读者对**本次素材**的理解是否受损？不受损就删。
- **篇幅随之下压**：政策/数据类稿正文控制在 1500—2000 字、小标题 4—5 个（2026-10-12 稿从 2823 字 / 8 节压到 1669 字 / 5 节）。不设硬性上下限，但超过 2200 字要先问自己是不是拓展过头了。

## 数据口径

- **能用数学关系验证的，先用数学关系验**：社保缴费基数必然满足「下限 = 本省上年度全口径城镇单位就业人员平均工资 × 60%，上限 = ×300%」。不满足的，要么是二手转述错了，要么是该省用了特殊口径（内蒙古、贵州的职工医保下限按社平 80% 核定；湖北、广东按社保年度 7 月—次年 6 月分段发文）。2026-10-09 这篇的 28 省数据全部这样验过才入表。
- 省份数据表格只收录已核实的：官方原文 > 权威媒体汇总（保留发布机关与日期）> 聚合站（只作线索，不作依据）。表注要写明单位、排列依据、口径差异与执行时间差异。
- **景区/景点天气分两级取数**：有景区专项预报就用专项（中国气象局名山稿件、市气象台景区专报），没有才用所在城市预报并在表注写明。
- 气温必须标明取值位置（山顶/山上/高山/市区），景区名后标所在地，如「泰山（山东泰安）」。
- 商业聚合源（天气 App、trip.com、天气网子站）不作依据；只用气象局系统与官方媒体转载。

## 自检脚本

- `selfcheck.py` 中表格字数单列；**不设字数上下限**，字数只在参考信息里输出，不参与合格判定（用户 2026-10-08 明确：不做字数要求，能清晰表达意思即可）。
- `selfcheck.py` 直接读交付 HTML：自动截取 `<div id="article">` 正文容器（剔掉工具栏、复制按钮、标题摘要预览区与脚本），靠两个约定还原结构——小标题段落以 `▪` 开头（→ `##`）、加粗用 `<strong>`（→ `**`）、表格 `<td>`/`<tr>`（→ `| ` 行），因此写 HTML 时必须保持这三个约定。
- 表格相关正则一律用 `[ \t]` 而非 `\s`，避免吃掉换行导致表格行被拼成一句。
- 超长句豁免两类：含 3 个以上顿号的列举句、含《》的文件全名引用句（长度不由写作者控制）。**注意：豁免只认顿号，逗号并列不豁免**——并列项要写成顿号（如"网约配送员超 1200 万人、快递员超 300 万人…"），否则按 55 字上限报错。
- 单句上限 55 字（超 40 字进参考信息）。分号与句号都切分句子，但**逗号不切**——逗号串起来的长句最容易踩。
- 核心词（`--keyword`）出现次数区间 **3—8**，超过 8 次出【堆砌】提示：靠改写表述（换成"这三类人""没有固定单位的人"）压次数，不要删掉必要信息。
- 摘要上限 120 字（差 1 字即报错，写完先按 115 字控）；导语首段建议 ≥54 字，让微信自动摘要位能独立成句。
- **新增行话与通知体机检**（2026-10-12）：`JARGON` 词表（18 个行话，命中输出【行话提示】放参考信息区，不阻断——行话不算错，但每个都是阅读门槛）；`NOTICE_LEAD_RE` 检测首段以「X 月 X 日」起句（进【建议修改】）；`NOTICE_PHRASES` 检测「现将有关事项」「特此通知」「为贯彻落实」等通知体措辞（进【建议修改】）。实测样例三项全部正确触发。
