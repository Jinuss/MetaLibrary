# 项目长期约定（article）

## 账号定位

- **全国号**，不是地方号。全国性题材（天气、政策、消费）保持全国视角，**正文与表格不下钻到单一城市**，除非该城市本身是全国性焦点（如北京、上海、广州）。
- 地方内容按**省级**或"省级 + 多城并列"表述；不因前一篇稿子涉及某地就在后续文章里惯性突出该地。

## 产出位置与命名

- 文章产出在 `article/` 根目录，**只输出一个文件** `YYYY-MM-DD-主题.html`（一键复制页）。用户 2026-10-08 明确：不再生成同名 `.md` 源稿；自检脚本已改成直接读 HTML。
- 根目录除文章文件外只应有 `.workbuddy/`。出现 8 位随机名、4 字节、内容为 `blat` 的文件 = 沙箱临时垃圾，直接删。判据用「根目录 + 4 字节」即可，无需逐个校验内容。每跑一次沙箱内自检约产生 20—40 个。
- 删除顺序（踩过的坑）：沙箱内 `find -delete`/`rm -f` 一律 Permission denied → 必须 `dangerouslyDisableSandbox`；跳出沙箱后 `find -delete` 仍会被拒，要对每个文件先 `attrib -R -S -H` 再 `rm -f`；**for 循环批量删会被 SIGTERM 打断**，改成一条命令跟一串文件名 `rm -f a b c …`（每次 10 个左右）最稳，删完立刻 `ls` 复核。

## 语体与格式（用户明确要求）

- 正文用**民生平实语体**（2026-10-08 由"官方通稿语体"修正而来）：平实、正常对话、有读者在场，像一位把文件读懂了的人用日常语言讲给读者听。判据是"念给没看过文件的人听，他能不能听懂；听懂但觉得像在被训话，也要改"。
  - **允许**：设问过渡（"婚假能休几天？"）、导航句（"下面先说数据，再说婚假怎么休"）、把读者位置写进段落（"准备结婚或刚登记的人……"）。
  - **避免公文腔**：依法办理、同步公布、还披露、文件明确、现将、予以、有关规定、享受相应待遇、统筹推进、稳妥有序；这类词自检会出【公文腔提示】。
  - **仍然禁止**：口语化短句收尾（"比什么都准""别拖到最后几天"）、加粗短句打头、祈使式叮嘱（记得/千万别/一定要）、撒娇催促抖机灵。
- 民生细分题材按此定语气：政策解读（先变化→"你这类人怎么办"）／办事指南（直给条件步骤）／生活服务（给场景判断）／数据发布（先来源数字→读者位置）／权益维护（谁能办、找谁、什么时限）。混合题材按读者的第一疑问定语气。
- 中文标点一律全角，引号用 `“ ”`；标题不超过 64 字且不含冒号，不用绝对化用语（最有效、全国第一、100%）与标题党表达（震惊、必看、紧急通知）。
- 成稿必须跑 `scripts/selfcheck.py` 兜底，零 ERROR 零 WARN 才算完成。

## 交付与编码

- HTML 存 UTF-8 无 BOM（头字节应为 `3c2144`），样式全内联，可一键复制到公众号后台。
- 表格最多 3 列，`table-layout:fixed` + 百分比列宽，不用 `<th>/<thead>`。

## 结构与编排（用户 2026-09-30 确认）

- **快查信息前置**：城市/景区等速查表放在「全国概况」之后、「分区域」之前，让读者第 2 屏拿到答案。
- **小标题用读者自己的词**：一律用省份名、城市名，不用气象区名（江淮/黄淮/江汉）和行业术语——读者无法判断自己属哪个区，且这类词在搜一搜里是零命中。唯一例外是专业统计口径（如气温距平按江南、华南发布），改动会失真，保留。
- **同一信息不重复**：与表格重复的城市单列条目一律删除；正文只留表格覆盖不到的增量。
- **必须有民生落点**（用户 2026-09-30 明确）：本号是民生号，不是资讯号。任何题材都要回答"所以呢"——删掉这篇文章，读者损失的是「知道了」还是「用得上」。天气稿必须落到出行（高峰时段、免费政策）、安全、体感；政策稿落到谁能办、怎么办、何时截止。落点用**事实与后果**陈述，不用叮嘱口吻（写"临近 24 时截止时点部分路段可能集中驶出"，不写"建议提前下高速"）。
- **天气稿优先补交通**：交通部门（交通运输部、公安部交管局、各省交通运输厅）的出行提示里有现成的官方预测——高速免费时段、流量峰值日、出程/返程高峰时段，比气象数据更贴近读者的动作，值得单独成节。
- **标题也要有落点**（用户 2026-09-30）：题材词（"天气""政策"）只说明写的是什么，落点词（"高速免费 7 天""最高 1 万元"）才说明读者能得到什么。标题须含至少一个落点词，并压在列表页展示的前 20 字内；核心检索词完整前置（如"国庆假期天气预报"是一个真实高频搜索词）。

## 数据口径

- **能用数学关系验证的，先用数学关系验**：社保缴费基数必然满足「下限 = 本省上年度全口径城镇单位就业人员平均工资 × 60%，上限 = ×300%」。不满足的，要么是二手转述错了，要么是该省用了特殊口径（内蒙古、贵州的职工医保下限按社平 80% 核定；湖北、广东按社保年度 7 月—次年 6 月分段发文）。2026-10-09 这篇的 28 省数据全部这样验过才入表。
- 省份数据表格只收录已核实的：官方原文 > 权威媒体汇总（保留发布机关与日期）> 聚合站（只作线索，不作依据）。表注要写明单位、排列依据、口径差异与执行时间差异。
- **景区/景点天气分两级取数**：有景区专项预报就用专项（中国气象局名山稿件、市气象台景区专报），没有才用所在城市预报并在表注写明。
- 气温必须标明取值位置（山顶/山上/高山/市区），景区名后标所在地，如「泰山（山东泰安）」。
- 商业聚合源（天气 App、trip.com、天气网子站）不作依据；只用气象局系统与官方媒体转载。

## 自检脚本

- `selfcheck.py` 中表格字数单列；**不设字数上下限**，字数只在参考信息里输出，不参与合格判定（用户 2026-10-08 明确：不做字数要求，能清晰表达意思即可）。
- `selfcheck.py` 直接读交付 HTML：自动截取 `<div id="article">` 正文容器（剔掉工具栏、复制按钮、标题摘要预览区与脚本），靠两个约定还原结构——小标题段落以 `▪` 开头（→ `##`）、加粗用 `<strong>`（→ `**`）、表格 `<td>`/`<tr>`（→ `| ` 行），因此写 HTML 时必须保持这三个约定。
- 表格相关正则一律用 `[ \t]` 而非 `\s`，避免吃掉换行导致表格行被拼成一句。
- 超长句豁免两类：含 3 个以上顿号的列举句、含《》的文件全名引用句（长度不由写作者控制）。

## 平台合规与防限流（用户 2026-10-09 要求写入 Skill）

- 依据微信运营规范 **3.27 非真人自动化创作**（AI/脚本替代真人写+发、托管批量连发 → 限流/删文/封号）与 **7.4 低价值 AIGC**（AI 占主体不标注、编造事实与数据 → 不进推荐池）。完整规则在 `references/platform-compliance.md`。
- **AI 只做副驾驶**：检索线索、列提纲、校语病、出标题候选。事实核对、角度、判断、案例必须人工完成。
- **每篇默认在文末加 AI 辅助创作声明**：「本文由作者选题与成稿，AI 仅用于资料整理和语句校对，核心观点与案例为人工整理。」措辞用"AI 辅助"，**不写"AI 生成"**（后者会被直接归到 7.4）。
- **原创声明别滥用**：天气稿、政策原文整理、纯数据汇编一律不标；只有形成独立判断与表达的稿件才标。已同步修正 `wechat-seo.md` 里"原创声明开启有助于权重"的旧表述。
- 语言层新增 `writing-rules.md` **G6 合规用语红线**：绝对化用语表（法定名词如"最低工资标准""最高缴费基数"不受限）、医疗财经保险法律时政只做官方口径转述、不用"网传/据悉/业内人士表示"、正文与评论区零引流（微信号/二维码/外链/私信领资料/关注后可见）。
- `selfcheck.py` 新增 4 项合规检查，输出前缀 `【合规】`：绝对化用语、引流痕迹、标题党表达、AI 辅助声明缺失；无资质领域词只出 `【合规提示】` 不阻断。两类现有稿件实测零误报。
